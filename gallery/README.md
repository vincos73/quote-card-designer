## Aggiornare la galleria

1. Aggiungi o modifica il profilo, le immagini e la voce in `references/catalogo-stili.yaml`. Gli stili fuori release hanno `release_candidate: false`. Per un V1 candidate aggiungi anche `v1_shortlisted: true`: mostra il badge «V1 candidate» e il filtro «Candidates», senza inserirlo nei selezionati. I due stati non possono essere attivi insieme.
2. Installa le dipendenze: `python3 -m pip install -r gallery/requirements.txt`.
3. Dalla radice del repository esegui `python3 gallery/build.py`. La build genera `gallery/dist/index.html` e una JPEG per ogni esempio. `dist/` è ignorata da Git perché deriva dai sorgenti.
4. Controlla il risultato e committa i sorgenti su GitHub.

La build conserva ricerca, filtri per categoria e release, profili YAML integrali e selettore degli esempi. Le immagini sono file separati: Sites rifiuta un singolo HTML oltre 25 MB.

Le categorie della gallery sono definite in `families` nel catalogo esteso. Ogni stile ha una categoria principale, assegnata per il linguaggio visivo che lo distingue; tecniche, soggetti e affinità trasversali restano ricercabili tramite tag e alias. Ogni categoria ha un nome e una breve descrizione che compare quando si seleziona il filtro. La revisione e le assegnazioni pubblicate sono documentate in [CATEGORIE.md](CATEGORIE.md). Il catalogo V1 distribuito resta uno snapshot separato della release.

Tutte le schede devono essere figli diretti di `section#catalogo.gallery`: quelle inserite dopo la chiusura della sezione diventano larghe quanto la pagina. La build verifica questa struttura e l'esistenza degli asset con `gallery/validate.py`. Puoi controllare anche una sorgente Sites con `python3 gallery/validate.py <checkout_path>/dist/index.html`. Quando inserisci schede in modo mirato, aggiungile prima della chiusura della griglia e ripeti il controllo prima della pubblicazione.

Per un nuovo profilo ancora senza prove visive, imposta `example_count: 0` e ometti i percorsi degli esempi: la scheda mostra «Anteprima da realizzare» e rende disponibile il YAML. Aggiungi immagini, note e prompt effettivi quando vengono realizzati; gli screenshot usati per studiare uno stile non sono esempi di quote card.

## Pubblicare sul Sites esistente

La pubblicazione richiede il plugin **Sites** con accesso al progetto `appgprj_6adb7b4f342881918cd48a4c247a3092`. La gallery ha accesso riservato al proprietario e agli ospiti autorizzati. Il manifest `gallery/.openai/hosting.json` conserva l'ID e la directory statica. Una credenziale Git di Sites è temporanea: non salvarla nel repository o nei segreti di GitHub.

Nel contesto Codex che dispone del plugin Sites:

1. Chiama `get_site` per verificare proprietario e pubblico corrente e `create_source_repository_write_credential` per ottenere la credenziale temporanea, senza richiedere una pubblicazione privata automatica.
2. Apri la sorgente Sites con lo `site-workflow.mjs` del plugin in una directory vuota. Invia la credenziale al processo tramite stdin, come indicato dallo skill Sites. Conserva il `checkout_path` restituito.
3. Esegui `python3 gallery/sync_to_site_checkout.py <checkout_path>` dalla radice del repository GitHub solo se tutta la build locale è pronta per la pubblicazione. Lo script sostituisce l'intera `dist/`: se contiene studi ancora in valutazione, prepara invece un aggiornamento limitato alle schede approvate conservando le altre schede e immagini pubblicate.
4. Richiama `site-workflow.mjs` nello stesso checkout, passando la credenziale e un `archivePath` temporaneo. Il risultato deve contenere `commit_sha` e `archive` della sorgente caricata.
5. Con accesso `custom` o altri pubblici condivisi, chiama `save_site_version` con quel `project_id`, `commit_sha` e `archive`, poi `deploy_site_version` con l'ID della versione salvata. Conserva il pubblico esistente. Usa `save_version_and_deploy_private` soltanto per un sito confermato come riservato al solo proprietario. Se il risultato non è terminale, consulta `get_deployment_status`.

Se il plugin Sites non è disponibile in Codex Cloud, la build può essere preparata e committata da lì, ma la pubblicazione sul Sites esistente deve essere eseguita in una chat con il plugin abilitato. Il repository da solo non fornisce una credenziale di pubblicazione.
